# Документация по скриптам Tampermonkey для шахматных сайтов

## Обзор системы

Система состоит из 10 модульных скриптов, каждый из которых отвечает за определённую функциональность. Скрипты взаимодействуют через общее хранилище GM (GreaseMonkey) и могут работать как независимо, так и совместно.

## Список скриптов

### 01_chessking_tracker.js - Основной трекер ChessKing
**Назначение**: Центральная система отслеживания прогресса решения задач на ChessKing с поддержкой режима обучения  
**Основные функции**:
- Отслеживание количества решённых задач в день
- Автоматический редирект на страницу задач при недостаточном прогрессе
- **Интеграция с режимом обучения** - временная приостановка требований задач во время обучения (9:00-10:00)
- Визуальный интерфейс с графиками прогресса и статистикой
- Расчёт средней и максимальной скорости решения
- Прогнозирование времени до завершения курса
- Обновление заголовка страницы с количеством оставшихся задач

**Домены**: `learn.chessking.com`  
**Настройки**:
- `courseId = 72` - ID курса ChessKing
- `minTasksPerDay = 2000` - **увеличенный** минимум задач в день для разблокировки

**GM ключи**:
- `initial_solved_${courseId}_${date}` - начальное количество решённых задач
- `daily_solved_${courseId}_${date}` - количество задач, решённых сегодня
- `cached_solved_${courseId}_${date}` - кэш: решено сегодня
- `cached_unlock_${courseId}_${date}` - кэш: осталось до разблокировки
- `training_completed_${date}` - **НОВОЕ**: проверка завершения обучения (чтение)

### 02_animation_autoclick.js - Анимации и автоклик ChessKing
**Назначение**: Ускорение интерфейса ChessKing для более быстрого решения задач  
**Основные функции**:
- Переопределение jQuery анимаций (мгновенное выполнение)
- Автоматический клик по кнопке "Следующее задание"
- Мониторинг изменений DOM для автоклика

**Домены**: `learn.chessking.com`  
**Технические детали**:
- Переопределяет `jQuery.animate`, `fadeIn`, `fadeOut`
- Использует `MutationObserver` для отслеживания появления кнопок
- Проверяет видимость элементов перед кликом

- **Фильтрация тем тренировок**: скрытие специфических тем на `/training/themes`

**Домены**: `lichess.org`  
**Разрешённые типы**: Блиц, Рапид, Blitz, Rapid

### 05_message_control.js - Контроль сообщений по задачам
**Назначение**: Ограничение отправки сообщений на основе количества решённых задач  
**Основные функции**:
- Подсчёт доступных сообщений на основе решённых задач
- Блокировка форм отправки при превышении лимита
- Визуальные индикаторы оставшихся сообщений
- Автоматический инкремент счётчика отправленных сообщений
- **Автоматическое определение активного трекера** - не требует конфигурации

**Домены**: `lichess.org/inbox/*`, `lichess.org/forum/team-*`  
**Соотношение**: 50 задач = 1 сообщение  
**GM ключи**:
- `messages_sent_${courseId}_${date}` - количество отправленных сообщений
- Читает `daily_solved_${courseId}_${date}` из любого трекера (01 или 09)

**Поддерживаемые формы**:
- Личные сообщения Lichess (`.msg-app__convo__post`)
- Форумы команд (`form.form3.reply`)

## Архитектура взаимодействия

### Обмен данными через GM Storage
Скрипты используют общие ключи для обмена данными:

**Основные ключи:**
```
daily_solved_${courseId}_${date}     // Основной трекер → Контроль сообщений
cached_unlock_${courseId}_${date}    // Основной трекер (кэш)
cached_solved_${courseId}_${date}    // Основной трекер (кэш)
messages_sent_${courseId}_${date}    // Контроль сообщений
```

**НОВОЕ: Ключи режима обучения:**
```
training_completed_${date}           // Скрипт #10 → Скрипты #01/#09 (отметка завершения)
```

### Схема зависимостей
```
01_chessking_tracker.js (центральные данные ChessKing)
    ↓ (предоставляет daily_solved_*)
05_message_control.js (использует данные о задачах)

09_lichess_tracker.js (центральные данные Lichess)
    ↓ (предоставляет daily_solved_* в том же формате)
05_message_control.js (совместим с любым трекером)

02_animation_autoclick.js ← независимый
03_chesscom_filter.js ← универсальный (любые платформы)  
04_lichess_filter.js ← универсальный (любые платформы)
05_message_control.js ← универсальный (любые трекеры)
06_url_blocker.js ← универсальный (любые платформы)
07_time_blocker.js ← универсальный (любые платформы)
08_turnir.js ← независимый (включает функции из 02)
10_training_redirect.js ← универсальный (любые платформы)
```

## Гонка загрузки при перезапуске браузера (v0.14)

**Симптом.** При перезапуске браузера (особенно когда восстанавливается сессия и разом
грузятся несколько вкладок) заблокированная страница успевает отрисоваться на 0.5–2
секунды раньше скрипта. В это окно можно отправить сообщение — блок-экран появляется
уже после. Причина не в коде: Tampermonkey стартует не мгновенно, а юзерскрипт не может
выполниться раньше, чем его внедрит расширение. Значит окно нужно закрывать не «раньше»,
а с других сторон.

**Что делает скрипт (`11_unified_chess_control.js`, v0.14):**

1. **Предохранитель отправки** (`SEND_GUARD_ENABLED`, функция `installSendGuard`).
   Ставится самым первым, до блок-экрана, в мире страницы (`unsafeWindow` — патч в
   песочнице Tampermonkey сайту не виден). Перехватывает все каналы отправки:
   `fetch`, `XMLHttpRequest`, кадры WebSocket с `msgSend`/`forumPost`, `sendBeacon`,
   событие `submit` в фазе capture и `HTMLFormElement.prototype.submit`
   (нативный submit не проходит ни через fetch, ни через XHR — без этого слоя дыра
   остаётся). Решение принимается по URL **запроса**, а не страницы, и только для
   методов POST/PUT/PATCH/DELETE — deny-лист в `CONFIG.sendGuard.deny`. Смысл:
   набрать текст занимает секунды, поэтому к моменту нажатия «Отправить» скрипт уже
   загружен и режет отправку, даже если блок-экран опоздал.
2. **Подмена адреса** (`SANITIZE_BLOCKED_URL`, функция `sanitizeBlockedUrl`).
   Перед показом блок-экрана адрес вкладки заменяется на безопасный (`/training`,
   `/puzzles`). Без этого сессия браузера восстанавливала именно `/inbox`, и окно гонки
   можно было получать повторно одним перезапуском.

Замер headless-Chrome 30.07.2026 (стенд: HTTPS-сервер + WebSocket-сервер, юзерскрипт
внедряется шимами GM_* на document-start): 20/20 проверок — отправка не уходит ни по
одному каналу, кадр `msgSend` не доходит до сервера, обычный кадр хода доходит
(игра не сломана), легальные POST-запросы сайтов проходят.

**Что остаётся за скриптом.** Первые миллисекунды до внедрения расширения полностью
закрывает только блокировка на уровне браузера. Chrome по политике `URLBlocklist`
не даёт даже начать загрузку страницы:

```bash
sudo defaults write /Library/Managed\ Preferences/com.google.Chrome URLBlocklist -array \
  "lichess.org/inbox" "lichess.org/forum" "lichess.org/team" "lichess.org/msg" \
  "lichess.org/ublog" "lichess.org/coach" "chess.com/messages" "chess.com/forum" \
  "chess.com/clubs" "chess.com/friends"
sudo killall cfprefsd
# проверка: chrome://policy → Reload policies → URLBlocklist
```

Готовый скрипт установки — `install_chrome_policy.sh` рядом с юзерскриптом.

## Stylus-шторка (v0.16)

Третий слой защиты от той же гонки — теперь и **визуальный**. Расширение
[Stylus](https://chromewebstore.google.com/detail/stylus/clngdbkpkpeebahjckkjfobafhncgmne)
внедряет CSS мгновенно даже на холодном старте браузера, когда Tampermonkey ещё
грузится. Пара работает так:

- userstyle `curtain.user.css` на **всех** сайтах прячет контент
  (`body { display:none }` + тёмный экран «⏳ Загрузка…»), пока на `<html>`
  нет атрибута `data-ucc-armed`;
- скрипт v0.16 ставит этот атрибут (`armCurtain`) только когда защита реально
  активна: конец инициализации на разрешённой странице, блок-экран
  `replaceDocument` (атрибут зашит прямо в записываемый `<html>`) или
  time-overlay `showBlockedOverlay`. При редиректе трекера шторка не снимается —
  контент запрещённой страницы не мелькает до навигации.

Итог: в первые 0.5–2 секунды после перезапуска браузера ребёнок видит тёмный
экран «Загрузка…» вместо живой страницы — ни прочитать, ни кликнуть. Если
Tampermonkey отключён или скрипт упал на середине инициализации, шторка остаётся
висеть (**fail-closed**): вечная «Загрузка…» лучше открытой переписки.

**Установка.** Stylus → открыть raw-ссылку
`https://raw.githubusercontent.com/vdrecords/crestrictions/main/curtain.user.css`
— Stylus сам предложит установить стиль (и будет обновлять его по этой ссылке).

**Порядок обновления безопасен в одну сторону.** Скрипт v0.16 без установленного
userstyle ничего не меняет: он лишь ставит атрибут, на который без Stylus никто
не смотрит. Поэтому сначала обновляется скрипт, потом ставится стиль. Обратный
порядок (стиль есть, скрипт < v0.16) даст вечную шторку на всех страницах —
не ставить `curtain.user.css`, пока Tampermonkey не подхватил v0.16.

**Отключение.** Выключить/удалить стиль в Stylus — скрипт продолжит работать
как в v0.15. Атрибут `data-ucc-armed` безвреден сам по себе.

## Швейцарские турниры на lichess (v0.15.0)

С мая 2026 раздел `/swiss` был закрыт целиком («турнир идёт долго, потеря времени»).
С v0.15.0 он открыт и работает по тем же правилам, что и Арена.

**Что разрешено:**

- `/swiss` — расписание швейцарок;
- `/swiss/<id>` — страница турнира и участие в нём.

**Что осталось закрыто:**

- `/swiss/new/<team>` — создание своего турнира (симметрично `/tournament/new` у Арены);
- `/team` — раздел команд. Ссылки на команду в карточках швейцарок скрываются
  автоматически (`initAutoHideBlockedPaths` строит CSS-правила из block-листа);
- чат зрителей (`.mchat`) — как и на остальных страницах.

**Фильтр отбора турниров.** Ровно тот же, что у Арены:

| Что в подписи турнира | Поведение |
| --- | --- |
| `10+0 • Рапид`, `5+0 • Блиц`, `30+0 • Классика` | видно |
| `1+0 • Пуля`, `2+1 • Пуля` | скрыто; появляется только когда открыто Bullet-окно (награда за задачи) |
| `½+0`, `¼+0` (UltraBullet) | скрыто всегда |
| `5+0 • Crazyhouse`, Atomic, 960 и прочие варианты | скрыто всегда, Bullet-окно их не открывает |

Реализация: строки расписания фильтрует `filterSwissRows` (классы `.ucc-blocked-swiss` —
навсегда, `.ucc-blocked-swiss-bullet` — снимается классом `body.ucc-bullet-window-open`);
на самой странице турнира работает `applyRules` — маркер `.swiss__meta`, контроль и тип
читаются из первого `<p>` («30+0 • Классика • Рейтинговый»). Если турнир не подходит,
скрываются кнопка «Участвовать» и доска.

**Проверка.** `repro_swiss.mjs` — headless-Chrome стенд на реальных страницах lichess
(сохранены в `fx_swiss/`, русская локаль, 2026-07-30):

```bash
# сертификат нужен один раз, рядом со скриптом
openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 30 \
  -subj "/CN=lichess.org" -addext "subjectAltName=DNS:lichess.org"
node repro_swiss.mjs          # ожидается 16/16

# контроль: на предыдущей версии проба обязана падать
SCRIPT_PATH=<путь к v0.14> node repro_swiss.mjs   # 0/1, «Раздел заблокирован»
```

## Полная разблокировка lichess: окно и награда (v0.18.0)

Настройка `LICHESS_FULL_UNLOCK_DATES` (v0.17) снимала с lichess.org все внутренние
ограничения скрипта — path-фильтр разделов, дневную цель задач, фильтр типов игр и
турниров, скрытие ссылок, блокировку отправки сообщений. Работала она как флаг «на весь
календарный день» и включалась только руками, по дате. В v0.18 у неё появились границы
по времени и автоматический триггер.

### 1. Разблокировка живёт внутри окна расписания

```js
const LICHESS_FULL_UNLOCK_MODE = 'schedule';   // 'schedule' (по умолчанию) | 'always'
const LICHESS_FULL_UNLOCK_WINDOWS = {          // персональные часы на дату
    // '2026-08-24': [['16:00', '17:00']]
};
```

* `'schedule'` — свобода действует ровно в окнах `SCHEDULE_WEEKLY` + `SCHEDULE_OVERRIDES`
  этого дня. В 09:00–12:00 и 16:00–18:00 lichess открыт целиком, в 13:00 и в 23:00 — нет.
* `'always'` — поведение v0.17 (весь календарный день).
* `LICHESS_FULL_UNLOCK_WINDOWS` перебивает режим и задаёт свои часы на конкретную дату.

Расписание блокировки компьютера (`timeBlocker`) разблокировка **не отменяла и раньше**
(критфикс v0.17.2) — вне окна страница закрыта блок-экраном в любой день. v0.18 убирает
и промежуточное состояние, когда контроль lichess уже снят, а окно ещё не открылось.

### 2. Разблокировка как награда за дневную норму

```js
const LICHESS_FULL_UNLOCK_ON_TASK_TARGET = true;   // мастер-тумблер награды
const LICHESS_FULL_UNLOCK_TASK_THRESHOLD = null;   // null = дневная норма задач
const LICHESS_FULL_UNLOCK_TASK_DISABLED_DATES = [];// даты, когда награды нет
```

Как только за сегодня решено задач не меньше дневной нормы (`TASK_TARGETS_WEEKLY` /
`TASK_TARGETS_SPECIAL`, либо явный порог), полная разблокировка включается сама и держится
до конца текущего окна. Счётчик задач привязан к дате и обнуляется в полночь, поэтому
награда не переносится на завтра. С 24.08.2026 дневной минимум поднят до **300 задач в
каждый день недели** (`TASK_TARGETS_WEEKLY = [300, 300, 300, 300, 300, 1000, 1000]`), то
есть и порог награды в будни теперь 300, а в выходные — 1000.
Порядок приоритетов: дата в `LICHESS_FULL_UNLOCK_DATES`
открывает день независимо от задач, `LICHESS_FULL_UNLOCK_TASK_DISABLED_DATES` отключает
только награду.

### 3. Состояние переключается без перезагрузки страницы

Раньше каждый модуль решал один раз при загрузке. Теперь `refreshFullUnlockState()`
тикает вместе с `timeBlocker` (раз в минуту, poll, `focus`, `visibilitychange`) и после
каждой засчитанной задачи:

| Что | Как переключается |
|-----|-------------------|
| CSS-скрытия фильтра lichess (лобби, карточки турниров, `.mchat`) | управляемый `<style id="ucc-lichess-filter-style">` гасится и возвращается |
| Скрытие ссылок на запрещённые разделы | `<style id="ucc-autohide-paths-style">` |
| Скрытие тематических `/training/*` | `<style id="ucc-lichess-training-style">` |
| Inline-скрытия `applyRules` (доска, кнопка «Участвовать», пресеты) | помечаются `data-ucc-filter-hidden` и снимаются при разблокировке |
| `sendGuard` (fetch/XHR/WebSocket/sendBeacon) | правила пересобираются при смене состояния, троттлинг 2 с |
| Path-фильтр `urlBlocker`, редирект трекера на `/racer` | проверяются на каждой навигации |

Норма выполнена в 17:10 — lichess открывается на той же странице; в 18:00 окно
закрывается, фильтр возвращается сам.

Трекер в разблокированный день больше **не выключается целиком**: снимается только
редирект на `/racer`, а счёт задач, окно прогресса и Bullet-награда продолжают работать
(до v0.18 `initTracker` выходил сразу, и решённые задачи переставали считаться — для
награды за норму это было бы фатально).

В окне прогресса появилась третья строка: `🔓 Норма выполнена — lichess открыт полностью
до 18:00` (или `Особый день — …`).

### Проверка

Приборы лежат рядом со скриптом, запускаются без сети и без установки пакетов
(нужен глобальный `puppeteer-core` и Chrome в `/Applications`):

```bash
node repro_full_unlock_logic.js     # 30/30 — чистая логика решения
node repro_full_unlock_dynamic.js   # 18/18 — Chrome, ускоренные часы (~70 c)
node repro_full_unlock_nav.js       # 10/10 — Chrome, навигация (~20 c)
```

* `repro_full_unlock_logic.js` — вырезает из скрипта настройки и функции решения и
  гоняет их на сценариях: дата, задачи, режимы окна, персональные часы, отдельный порог,
  стоп-листы, chess.com, `SCHEDULE_OVERRIDES`.
* `repro_full_unlock_dynamic.js` — настоящий Chrome, поддельная страница lichess.org,
  часы идут ×60: норма выполняется в 17:00 → фильтр и скрытие ссылок гаснут без
  перезагрузки, в 18:00 возвращаются вместе с блок-экраном расписания.
* `repro_full_unlock_nav.js` — `/inbox` и редирект на `/racer` в сочетаниях
  день / час / норма.

Блок-экран расписания на закрытых часах этими приборами не измеряется: они внедряют
скрипт раньше, чем это делает Tampermonkey (`documentElement` ещё `null`), и документ
рвётся на редиректе трекера. Разовый A/B со старой версией показал в этом сценарии
идентичное поведение v0.17.2 и v0.18.0.

## Устранение неполадок

### Скрипты не работают
1. Проверьте совпадение доменов в `@match`
2. Убедитесь, что Tampermonkey включён
3. Проверьте консоль браузера на ошибки
4. **Убедитесь, что не включены конфликтующие скрипты**

### Данные не синхронизируются
1. Проверьте, что основной трекер (01) запущен
2. Убедитесь, что скрипты используют одинаковый `courseId`
3. Проверьте права доступа к GM_getValue/GM_setValue

### Конфликты скриптов
1. **Используйте только один из рекомендованных режимов**
2. В турнирном режиме отключите скрипты 01-07
3. Не запускайте одновременно 07, 08 (конфликт блокировки)
4. **НЕ используйте одновременно 01 и 09** (конфликт трекеров)
4. Проверьте, что нет дублирующихся `@match` директив
5. Убедитесь в правильном порядке загрузки скриптов
